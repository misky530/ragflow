# SQL Assistant — 开发者视角

---

## 一、节点类型全景

| 节点类型 | 实例 | 作用 | 是否新出现 |
|---|---|---|---|
| `Begin` | begin | 对话入口 | — |
| `Retrieval` | Schema Retrieval × 3 | 并行检索表结构/字段说明/查询示例 | — |
| `Agent` | Text-to-SQL Agent | 根据检索结果生成 SQL | — |
| `ExeSQL` | SQL 执行节点 | **真正执行 SQL，返回数据库结果** | **首次出现** |
| `Message` | 输出节点 | 格式化展示查询结果 | — |

---

## 二、数据流分析

```
begin
  └── sys.query（用户自然语言问题）
          │
          ├────────────────────────────────┐
          ↓                                ↓                         ↓
Retrieval（表结构）    Retrieval（字段说明）    Retrieval（查询示例）
  检索数据库 Schema     检索业务语义说明         检索历史 SQL 样例
  输出 @output          输出 @output              输出 @output
          │                                │                         │
          └────────────────┬───────────────┘
                           ↓
              Text-to-SQL Agent
              输入：
                - sys.query（用户问题）
                - 三个 Retrieval 的检索结果（Schema + 语义 + 示例）
              任务：生成正确的 SQL 查询语句
              输出：@content（SQL 文本）
                           │
                           ↓
                      ExeSQL 节点
              输入：Agent@content（SQL 语句）
              操作：连接数据库，执行 SQL
              输出：@result（查询结果，JSON 或表格格式）
                           │
                           ↓
                   Message（格式化输出）
```

---

## 三、ExeSQL 节点详解

`ExeSQL` 是 RAGFlow 中的**数据库执行节点**，配置项包括：

```
数据库连接：
  - db_type: MySQL / PostgreSQL / SQLite / ...
  - host / port / database
  - username / password

执行配置：
  - 输入变量：指向 Text-to-SQL Agent 的 SQL 输出
  - 超时时间：防止长查询阻塞流程
  - 结果行数限制：防止返回过大数据集
```

**安全警告**：模板默认不限制 SQL 类型，若不加限制，用户可能通过自然语言触发 DELETE/DROP 等危险操作。**生产部署必须**：
1. 使用只读数据库账号
2. 或在 Text-to-SQL Agent 的 system prompt 中明确要求"只生成 SELECT 语句"

## 四、Schema 知识库建设

这是模板能否准确工作的**最关键前置条件**：

### 表结构知识库（必须）
每张表写一个文档片段：
```
表名：orders（订单表）
字段：
  - order_id (INT): 订单唯一ID
  - user_id (INT): 用户ID，关联 users 表
  - amount (DECIMAL): 订单金额，单位元
  - status (INT): 订单状态，1=待付款 2=已付款 3=已发货 4=已完成
  - created_at (DATETIME): 订单创建时间
```

### 字段说明知识库（重要）
补充业务语义，LLM 无法从字段名猜到的含义：
```
status=1: 待付款（下单未支付）
status=2: 已付款（支付成功，等待发货）
"近30天": 指 created_at >= DATE_SUB(NOW(), INTERVAL 30 DAY)
```

### 查询示例知识库（提升准确率）
常见查询的 SQL 样例（few-shot）：
```
问题：今日销售额
SQL：SELECT SUM(amount) FROM orders WHERE DATE(created_at) = CURDATE() AND status >= 2
```

## 五、已知局限

| 局限 | 影响 | 缓解方案 |
|---|---|---|
| 复杂 SQL 生成不稳定 | 多表 JOIN、窗口函数准确率低 | 增加更多 few-shot 示例 |
| Schema 变更不自动同步 | 数据库加了新表，知识库不知道 | 建立 Schema 变更同步机制 |
| 无 SQL 执行结果缓存 | 相同查询重复执行 | 接入缓存层 |
| 权限控制依赖数据库账号 | 无法基于用户角色做字段级权限 | 使用不同权限的数据库账号分配给不同用户组 |

## 六、落地配置

```
1. 建立三个 RAGFlow 知识库：
   - 表结构库（按表整理文档）
   - 字段语义库（业务术语解释）
   - SQL 示例库（历史查询样例）

2. 导入模板，配置三个 Retrieval 节点分别绑定对应知识库

3. 配置 ExeSQL 节点的数据库连接（使用只读账号！）

4. 配置 Text-to-SQL Agent 的 system prompt：
   - 说明数据库类型（MySQL/PG）的方言差异
   - 要求只生成 SELECT 语句
   - 说明日期函数的使用规范

5. 测试5~10个典型查询，验证 SQL 准确性
```
