# SQL Assistant — 业务视角

---

## 一、ROI 测算

```
当前状态：业务人员需要数据时
  提需求 → 数据工程师排队 → 取数 → 返回 → 通常 1~3天

引入 SQL Assistant 后：
  自然语言提问 → 秒级返回数据
  数据工程师从"取数机器"解放，专注数据建模和分析

ROI：
  数据工程师节省 30~50% 的取数时间
  业务团队决策速度提升（从天到秒）
```

---

## 二、目标客户

### 优先（高价值）
- **数字化程度高的中大型企业**：有自建数据库，业务人员有频繁取数需求
- **数据驱动的电商/零售公司**：销售、运营、产品每天需要大量数据支撑决策
- **SaaS 公司**：内部运营数据查询需求高，数据团队资源紧张

### 次优
- **传统企业数字化转型项目**：作为"让业务人员用数据"的切入点

---

## 三、核心销售话术

**对业务负责人**：
> "你的团队需要数据时，要等多久？SQL Assistant 让他们用中文提问，秒级返回数据。不用写 SQL，不用等数据团队，自己就能取数。"

**对 IT/数据团队**：
> "你们的数据工程师每天有多少时间在处理取数请求？这个工具让业务自助取数，你们可以把时间用在更有价值的数据建模和分析上。"

---

## 四、关键风险（必须在销售前确认）

| 风险 | 严重程度 | 应对 |
|---|---|---|
| **数据安全**：用户可能查到不应查的数据 | ★★★★★ | 使用只读账号 + 字段级权限控制 |
| **SQL 错误**：生成的 SQL 逻辑有误，返回错误数据 | ★★★★☆ | 关键数据需人工核验，不能盲信 |
| **数据库性能**：复杂查询可能影响生产库性能 | ★★★☆☆ | 连接只读副本，设置查询超时 |

**销售时必须向客户说明安全配置要求**，否则可能造成数据泄露事故。

---

## 五、一句话总结

> SQL Assistant 是 RAGFlow 模板库中**商业价值最高、但部署风险也最高**的模板——它把数据自助查询的门槛从"会写 SQL"降到"会说话"，ROI 极其清晰；但必须严格做好数据库权限控制，否则安全风险不可接受。
