# Trip Planner — 开发者视角

---

## 一、架构概览

```
begin（conversational，开场白）
  ↓
Agent:OddGuestsPump - Tour Guide Agent
  （deepseek-chat，max_rounds=5，max_tokens=256，无工具）
  ↓
Agent:RichTermsCamp - Transit & Stay Agent
  （deepseek-chat，max_rounds=5，max_tokens=256，TavilySearch + TavilyExtract）
  ↓
Agent:WeakCarrotsTan - Result Generator
  （deepseek-chat，max_rounds=5，max_tokens=256，无工具）
  ↓
Message:ThickEyesUnite
```

---

## 二、节点详解

### Begin 节点
```json
{
  "mode": "conversational",
  "enablePrologue": true,
  "prologue": "Hi! I'm here to help plan your trip. Any destination in mind?"
}
```
对话模式，有开场白引导用户输入。

### Tour Guide Agent（节点 1）
- `llm_id`: `deepseek-chat@DeepSeek`
- `temperature`: 0.1，`max_tokens`: 256，`max_rounds`: 5
- **无工具**（纯 LLM 规划，基于自身知识）
- **职责**：指定出发地、目的地、行程天数，制定每日活动框架
- **系统提示重点**：明确要求"仅输出工具返回内容"用于后续 Agent 使用

### Transit & Stay Agent（节点 2）
- `llm_id`: `deepseek-chat@DeepSeek`
- `temperature`: 0.1，`max_rounds`: 5
- **工具**：
  - TavilySearch（搜索深度 basic，max_results 5，include_raw_content true）
  - TavilyExtract（抓取特定页面详情）
- **输入**：`{sys.query}` + `{Agent:OddGuestsPump@content}`
- **职责**：基于行程框架搜索交通/住宿选项，匹配日期、目的地、预算

### Result Generator（节点 3）
- `llm_id`: `deepseek-chat@DeepSeek`
- `temperature`: 0.1，`max_rounds`: 5
- **无工具**（纯整合）
- **输入**：`{sys.query}` + `{Agent:OddGuestsPump@content}` + `{Agent:RichTermsCamp@content}`
- **职责**：整合行程+交通住宿，输出结构化、可执行的完整旅行计划

---

## 三、数据流分析

```
用户输入 → Tour Guide Agent（纯 LLM）
              ↓ 行程框架
          Transit & Stay Agent
              ├── TavilySearch（搜索交通/住宿选项）
              └── TavilyExtract（抓取页面详情）
              ↓ 交通住宿方案
          Result Generator（接收3个输入：原始查询+行程框架+交通住宿）
              ↓
          Message（输出最终计划）
```

**关键设计**：Result Generator 同时接收 `sys.query`、`OddGuestsPump@content`、`RichTermsCamp@content` 三路输入，确保最终整合有完整上下文。

---

## 四、参数配置分析

| 参数 | 值 | 原因 |
|---|---|---|
| 所有 Agent temperature | 0.1 | 旅行计划需要准确，不能发散 |
| max_tokens | 256（所有 Agent） | 偏低——可能导致长行程输出被截断 |
| max_rounds | 5（所有 Agent） | 对话模式需要多轮，但工具调用也消耗 rounds |
| frequency_penalty | 0.7 | 防止重复描述（行程容易重复用语） |
| TavilySearch include_raw_content | true | 需要原始内容提取价格、时间等细节 |

**潜在问题**：`max_tokens=256` 对所有 Agent 都偏低，行程规划通常需要 1000+ tokens。建议在生产部署时调高至 2048+。

---

## 五、部署要点

```
1. 配置 TavilySearch 和 TavilyExtract 的 API Key
2. 调高 max_tokens（256 对行程生成不够，建议 ≥ 2048）
3. 对话模式下，sys.query 在每轮对话中更新——确保后续 Agent 引用的是最新查询
4. Tour Guide Agent 不用工具，但其 prompt 要求基于实时信息——注意：它实际上用的是模型知识，不是实时数据
5. 测试边界："巴黎 5 天行程" vs "不想坐夜车，预算 5000，要有儿童友好酒店"
```
