# Customer Service — 开发者视角

## 一、节点类型全景

| 节点类型 | 实例 | 作用 | 是否新出现 |
|---|---|---|---|
| `Begin` | begin | 对话入口 | — |
| `Categorize` | 意图分类器 | 4类意图识别，路由分支 | — |
| `Agent` × 4 | 售前/售后/投诉/通用 Agent | 各分支的专业回答 | — |
| `VariableAggregator` | 输出汇合器 | **汇合4路分支输出为单一变量** | **首次出现** |
| `Message` | 输出节点 | 展示最终回答 | — |

## 二、数据流分析

```
begin
  └── sys.query（用户问题）
          │
          ↓
Categorize（意图识别）
  分类：售前 / 售后 / 投诉 / 其他
          │
    ┌─────┼──────────┬──────────┐
    ↓     ↓          ↓          ↓
售前 Agent 售后 Agent 投诉 Agent 通用 Agent
  @content  @content   @content   @content
    │         │          │          │
    └─────────┴──────────┴──────────┘
                    │
                    ↓
        VariableAggregator
        收集所有分支的 @content
        输出：@aggregated（实际执行分支的内容）
                    │
                    ↓
              Message → 用户界面
```

## 三、VariableAggregator 工作机制

`VariableAggregator` 是 RAGFlow 的**多路输出汇合节点**，解决分支工作流的收束问题：

```
工作原理：
  接收来自多个上游节点的变量
  每次执行时，只有一个分支实际运行（路由的结果）
  VariableAggregator 收集所有注册变量，
  过滤掉未执行分支的空值，
  输出实际有值的那个分支的内容

配置示例：
  aggregated_vars:
    - source: "Agent:售前@content"
    - source: "Agent:售后@content"
    - source: "Agent:投诉@content"
    - source: "Agent:通用@content"
  output: @aggregated（取非空值）
```

**与 StringTransform 的区别**（参考 customer_review_analysis 的问题）：
- `StringTransform` 是字符串拼接，不区分已执行/未执行
- `VariableAggregator` 专门处理分支汇合，只取有值的那个

## 四、Categorize 节点的配置质量

每个分类定义需要精心设计：

```
分类：售后支持（After-sales support）
  描述：用户在购买产品后遇到的使用问题、产品故障、功能不理解
  示例：
    1. 我买的产品用不了怎么办
    2. 这个功能在哪里设置
    3. 产品收到了但有损坏
  路由到：售后 Agent
```

**关键**：描述和示例的质量决定分类准确率。示例要有代表性，且要覆盖不同表达方式。

## 五、各分支 Agent 的知识库配置建议

```
售前 Agent
  知识库：产品介绍、价格方案、竞品对比
  System prompt 风格：积极推介，突出产品价值

售后 Agent
  知识库：操作手册、FAQ、视频教程索引
  System prompt 风格：耐心引导，步骤清晰

投诉 Agent
  知识库：退款政策、赔偿方案、升级处理流程
  System prompt 风格：安抚情绪，快速给出解决方案

通用 Agent
  知识库：所有知识库（或通用 FAQ）
  System prompt 风格：友好、诚实说明能力边界
```

---

## 六、落地配置

```
1. 准备4套知识库（各分支独立）

2. 配置 Categorize 节点：
   - 每类添加 5~10 个具有代表性的示例
   - 描述要覆盖边界情况（"收到损坏商品" 归售后还是投诉？）

3. 为每个 Agent 配置对应知识库和专业 system prompt

4. 配置 VariableAggregator，注册所有4路分支输出

5. 测试各路分支：
   - 确保各类问题都路由到正确分支
   - 重点测试边界问题（模糊问题如何分类）
```
