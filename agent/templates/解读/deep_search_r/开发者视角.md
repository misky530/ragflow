# Deep Search R — 开发者视角

---

## 一、架构概览

```
begin → Agent:NewPumasLick（主控，qwen-max）
              ├── Web Search Specialist（子 Agent，qwen-plus + TavilySearch）
              ├── Content Deep Reader（子 Agent，TavilyExtract）
              └── Research Synthesizer（子 Agent）
              ↓
         Message:OrangeYearsShine
```

**架构类型**：主控 Agent（qwen-max）+ 3 个嵌套子 Agent，动态调度

---

## 二、主控 Agent 详解

### Strategy Research Director（主控）
- `llm_id`: `qwen-max@Tongyi-Qianwen`（注意：使用 qwen-max，而非 DeepSeek）
- `temperature`: "0.1"（字符串格式，精确控制）
- `parameter`: "Precise"
- `max_rounds`: 3
- **系统提示框架**（极为详细）：
  - 执行框架：3 个阶段 × 明确时间预期（Stage1: 2-3min, Stage2: 3-5min, Stage3: 5-8min）
  - 查询分类算法：Depth-First / Breadth-First / Straightforward
  - 质量门控标准：每个阶段有成功/失败的具体指标
  - 自适应策略：失败恢复、资源分配、时间约束处理
  - 语言自适应：自动检测并保持一致
  - 执行示例：3 个完整执行示例（depth/breadth/straightforward 各一）

## 三、子 Agent 详解

### Web Search Specialist
- `llm_id`: `qwen-plus@Tongyi-Qianwen`（比主控低一档，节省成本）
- `max_rounds`: 1（单轮搜索）
- `temperature`: 0.2（false → 不启用）
- **工具**：TavilySearch
- **核心约束**：只发现 URL，**绝不读取内容**（严格职责边界）
- **输出格式**：`RESEARCH_URLS:` 结构，含 5 个优质 URL + 每个 URL 的提取重点

```
RESEARCH_URLS:
1. https://...
   - Type: Government Report
   - Value: 官方统计数据
   - Extract Focus: 关键指标、政策时间线
...
```

### Content Deep Reader
- **工具**：TavilyExtract（非 TavilySearch）
- **职责**：读取 Web Search Specialist 提供的 URL，结构化提取内容
- **质量目标**：80%+ URL 成功提取率

### Research Synthesizer
- **职责**：整合提取内容，生成 McKinsey 风格战略报告
- **目标**：~2000 字，有清晰章节、可行建议、多源引用

---

## 四、数据流

```
Stage 1: 主控 → Web Search Specialist
         Web Search Specialist 调用 TavilySearch × N 次
         返回 5 个 URL 结构化列表
         存入共享上下文（RESEARCH_URLS）

Stage 2: 主控 → Content Deep Reader  
         Content Deep Reader 调用 TavilyExtract 逐 URL 提取
         返回结构化内容（EXTRACTED_CONTENT）
         
Stage 3: 主控 → Research Synthesizer
         Research Synthesizer 基于 ANALYSIS_INSTRUCTIONS 框架生成报告
         输出 ~2000 字战略报告
         
主控合并输出 → Message
```

## 五、关键参数分析

| 参数 | 值 | 说明 |
|---|---|---|
| 主控 llm_id | qwen-max | 最强模型，用于复杂协调推理 |
| Web Search Specialist llm_id | qwen-plus | 降级模型，搜索任务不需要 max |
| 主控 max_rounds | 3 | 最多 3 轮协调（1轮/阶段） |
| Web Search Specialist max_rounds | 1 | 严格单轮，控制搜索成本 |
| TavilySearch max_results | 5 | 质量优先，不求数量 |
| TavilySearch include_raw_content | true | 需要完整内容用于深度提取 |

## 六、与 deep_research 的技术差异

| 维度 | deep_research | deep_search_r |
|---|---|---|
| 主模型 | 未指定或 DeepSeek | qwen-max（Tongyi） |
| 子 Agent 模型 | 单一模型 | 分级（qwen-max + qwen-plus）|
| Prompt 复杂度 | 中 | 极高（含完整方法论框架）|
| 查询分类 | 无 | Depth/Breadth/Straightforward |
| 质量门控 | 无 | 3 阶段明确标准 |
| 自适应策略 | 无 | 失败恢复 + 资源动态分配 |

---

## 七、部署要点

```
1. 配置 Tongyi-Qianwen API（qwen-max 和 qwen-plus）
2. 配置 TavilySearch 和 TavilyExtract API Key
3. 注意 qwen-max 成本较高——主控 max_rounds=3 足够，勿调高
4. Web Search Specialist max_rounds=1 是有意设计，防止搜索阶段过度消耗
5. 全流程 10~15 分钟是正常的，用户需要适当的等待提示
6. 中文研究问题：系统自动切换为中文来源优先策略
```
