# Deep Search R — 产品经理视角

---

## 一、目标用户与核心痛点

| 用户类型 | 核心需求 | 当前痛点 |
|---|---|---|
| **战略咨询顾问** | 快速整合多源信息，出有引用的报告 | 手动信息整合耗时 8~16 小时/报告 |
| **销售情报团队** | 竞品研究、市场进入分析 | 信息分散，无法快速形成结论性报告 |
| **市场营销总监** | 行业趋势分析，为决策提供依据 | 内部研究能力有限 |
| **政策研究人员** | 跨源信息汇总，政策影响评估 | 政策解读需要多角度验证 |

**核心价值主张**：把"战略研究"从"专业咨询团队数天工作"压缩到"几分钟内输出 2000 字 C-Suite 级报告"——附带引用来源，可直接作为决策依据。

## 二、功能设计的 PM 逻辑

### 2.1 查询分类系统 — 研究方法论的核心

主控 Agent 会自动将研究问题分类为三种类型，并采用不同策略：

```
深度优先（Depth-First）：同一主题多角度分析
  → 适合："什么导致加密货币市场波动？"
  → 策略：3~5 个子 Agent 分析不同视角（技术/监管/心理）

广度优先（Breadth-First）：多个独立子问题并行
  → 适合："对比5国税收体系"
  → 策略：并行 Agent 各负责一个国家

直接查找（Straightforward）：简单事实性问题
  → 适合："Tesla 当前股价"
  → 策略：单 Agent 快速检索
```

**PM 洞察**：这个分类系统是 deep_search_r 相比 deep_research 的核心差异。它让 AI 的研究方法更接近人类专家——不是用同一套方法处理所有问题，而是根据问题类型选择最优策略。

### 2.2 三阶段质量门控 — 保证报告质量的关键机制

每个阶段有明确的验收标准：

| 阶段 | 成功标准 | 失败标准 |
|---|---|---|
| Stage 1: URL 发现 | 5 个优质 URL，来源多样（学术/官方/行业/新闻） | URL < 3 个，来源单一 |
| Stage 2: 内容提取 | 80%+ URL 提取成功，有结构化数据 | < 60% 提取成功率 |
| Stage 3: 报告生成 | 2000+ 字，有明确建议，多源引用 | < 500 字，结论模糊 |

**PM 洞察**：质量门控是企业级产品与普通 AI 工具的核心差异。用户付出时间等待，期望获得可直接使用的输出，而不是需要再次加工的草稿。

### 2.3 语言自适应 — 全球化设计

系统自动检测用户语言，并在整个 pipeline 中保持一致（包括搜索策略、来源选择、报告语言）。

## 三、产品边界

### 适用场景
- 市场进入分析
- 竞品情报报告
- 行业趋势研究
- 政策影响评估
- 投资决策支撑材料

### 不适用场景

| 场景 | 原因 |
|---|---|
| **实时财务数据** | 需要专用财务 API，Tavily 不能保证实时性 |
| **独家非公开信息** | 只能访问互联网公开内容 |
| **法律/医疗正式建议** | AI 报告不能替代持牌专业人士意见 |
| **超短时间需求** | 三阶段完整执行需要 10~15 分钟 |

## 四、产品成熟度评估

| 评估维度 | 评分 | 说明 |
|---|---|---|
| **需求真实性** | ★★★★★ | 企业研究是持续性刚需 |
| **报告质量** | ★★★★☆ | prompt 极详细，但质量依赖来源质量 |
| **执行稳定性** | ★★★☆☆ | 3 阶段串行，任一阶段失败影响全链路 |
| **方法论严谨性** | ★★★★★ | 查询分类 + 质量门控是亮点 |

---

## 五、迭代方向

1. **专业数据库接入**：Bloomberg、CNKI、PubMed 等专业数据源
2. **报告模板定制**：支持不同咨询风格（McKinsey/BCG/Bain/学术）
3. **知识库增强**：允许上传私有文档作为补充信息源
4. **并行研究加速**：深度优先/广度优先时并行调用子 Agent，缩短总时间
