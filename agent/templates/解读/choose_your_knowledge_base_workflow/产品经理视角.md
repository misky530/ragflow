# Choose Your Knowledge Base Workflow — 产品经理视角

---

## 一、与 Agent 版本的核心差异

这两个模板的用户体验完全相同，差异在于**内部实现方式**：

| 维度 | Agent 版 | Workflow 版（本模板） |
|---|---|---|
| Retrieval 控制权 | Agent 自主决定 | 执行引擎强制 |
| 检索次数 | Agent 可多次检索 | 固定一次 |
| 行为可预测性 | 较低（LLM 灵活决策） | 高（流程固定） |
| 调试难度 | 较高 | 低（流程透明） |
| 适合问题复杂度 | 复杂、需要多轮检索 | 简单直接的查询 |

**PM 洞察**：RAGFlow 提供两个版本，本质上是在给开发者做**架构选型参考**——相同的用户需求，根据团队对可控性还是灵活性的偏好，选择不同实现路径。

---

## 二、何时选 Workflow 版？

推荐选 Workflow 版的场景：
- 团队技术能力有限，需要**流程透明、易于调试**的实现
- 问题类型简单，**一次检索足够**解答
- 需要**精确控制** Retrieval 参数（Top-K、相似度阈值）
- 企业客户要求**可审计的固定流程**

推荐选 Agent 版的场景：
- 问题复杂，可能需要**多步检索**才能回答
- 需要 Agent **自主判断是否需要检索**（某些问题可直接回答）
- 团队对 LLM Agent 行为有经验
