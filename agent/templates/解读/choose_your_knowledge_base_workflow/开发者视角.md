# Choose Your Knowledge Base Workflow — 开发者视角

---

## 一、节点类型全景

| 节点类型 | 实例 | 作用 |
|---|---|---|
| `Begin` | begin | 下拉选择知识库 + 接收用户问题 |
| `Retrieval` | 独立 Retrieval 节点 | 按选定知识库强制执行一次检索 |
| `Agent` | 回答 Agent | 接收检索结果，生成最终回答 |
| `Message` | 输出节点 | 展示回答 |

---

## 二、数据流分析

```
begin
  ├── begin@knowledge_base（下拉选择的知识库 ID）
  └── sys.query（用户问题）
          │
          ↓
Retrieval 节点（独立节点，非 Agent 内置工具）
  配置：
    knowledge_base_id = {begin@knowledge_base}  ← 动态绑定
    query = sys.query
    top_k = N
    similarity_threshold = X
  输出：@output（检索到的文档片段列表）
          │
          ↓
Agent
  输入：
    - sys.query（用户问题）
    - {Retrieval@output}（检索结果，注入 context）
  任务：基于检索结果生成回答
  输出：@content
          │
          ↓
Message → 用户界面
```

---

## 三、独立 Retrieval 节点 vs Agent 内置 Retrieval

**独立 Retrieval 节点的优势**：

1. **参数完全可控**：Top-K、相似度阈值、检索模式在节点层面显式配置，不依赖 Agent 的隐式行为
2. **结果可观测**：Retrieval 的输出 `@output` 是独立变量，可以在后续节点中直接引用或检查
3. **单次确定性执行**：图引擎保证 Retrieval 在 Agent 之前恰好执行一次

**可配置的关键参数**：
```
top_k: 返回文档片段数（建议 3~8，过多稀释上下文质量）
similarity_threshold: 相似度阈值（建议 0.3~0.5，太高则检索结果为空）
retrieval_mode: 向量检索 / 全文检索 / 混合检索
rerank: 是否启用重排序模型（提升精准度，增加延迟和成本）
```

---

## 四、与 Agent 版的代码层差异

```
Agent 版（choose_your_knowledge_base_agent）:
  Agent 节点配置中：
    tools: [{ type: "retrieval", knowledge_base_ids: ["{begin@knowledge_base}"] }]
  → Agent 自主决定调用时机

Workflow 版（本模板）:
  图中独立的 Retrieval 节点：
    knowledge_base_id: "{begin@knowledge_base}"
    query: "{sys.query}"
  → 执行引擎在 Agent 之前强制调用
```

---

## 五、调试技巧

Workflow 版的最大优势是调试友好：
- 可以在 `Retrieval@output` 处直接查看检索结果
- 如果 Agent 回答质量差，先检查 Retrieval 输出——是检索问题还是生成问题
- 可以单独测试 Retrieval 节点，不需要走完整流程
