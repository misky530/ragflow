## 一、目标用户与核心痛点

这个模板解决的是**企业客服/运营团队的评论处理效率问题**。

| 用户类型 | 核心需求 | 当前痛点 |
|---|---|---|
| 客服主管 | 把客户评论快速分发到对应部门处理 | 人工阅读分类耗时，高峰期积压严重 |
| 电商运营 | 实时监控评论情感，好评差评分流处理 | 差评漏看导致问题未被跟进，影响店铺评分 |
| 产品体验团队 | 收集售后问题反馈，快速响应 | 问题反馈路径长，经由多层转发才到达相关人 |
| 品牌营销团队 | 收集正面口碑用于内容复用 | 好评淹没在系统里，没有人主动整理 |

**核心价值主张**：评论进来，自动分类，直达对应部门邮箱——0人工干预，响应时间从"几小时"压缩到"几秒"。

## 二、功能设计的 PM 逻辑

### 2.1 两级分类策略 — 为什么不用一级分三类？

模板设计了两层分类而非一层分三类：

```
第一层（粗分）：正面 / 负面
第二层（细分，仅负面）：售后问题 / 物流问题
```

**PM 洞察**：这个设计有两层考量：

1. **降低误判风险**：一次性把评论分成三类，模型需要同时判断情感和问题类型，容易混淆。先判断情感（更简单的二分类），再对负面评论做细分（范围更小），每一步的判断难度都更低，准确率更高。

2. **扩展性更好**：正面评论未来可以再细分（产品好评/服务好评/物流好评），无需重构整个流程，只需在第一层之后再加一个 Categorize 节点。

### 2.2 三个独立 Email 节点 — 为什么不共用一个？

三个部门各有一个独立 Email 节点（而非一个节点根据条件发送不同邮件）。

**PM 洞察**：这是**部门隔离**的设计原则：
- 每个部门有自己的收件邮箱、发件配置、邮件主题
- 日后某个部门调整邮箱或格式，只改自己的节点，不影响其他部门
- 若需要给某个部门增加抄送人，也是独立配置

### 2.3 StringTransform 汇总状态 — 追踪发送结果

三个邮件节点的发送状态（`success: true/false`）被合并为一个字符串输出给用户。

**PM 洞察**：这是**过程可追溯**的设计。用户（客服系统操作员）可以看到本次评论是否成功触达相关部门，而不是盲目相信"已处理"。这在企业内部系统场景下是基本的审计需求。

### 2.4 Prologue 欢迎语 — 定位为对话式工具

```
"Hi! I'm your customer review analysis assistant. 
 You can send a review to me."
```

系统以对话模式启动，支持持续输入评论。

**PM 洞察**：这个设计暗示了两种使用场景：
- **手动模式**：客服人员把收到的评论逐条粘贴进来处理
- **自动模式**（需二次开发）：对接电商平台 API，自动推送评论到这个 Agent

## 三、产品边界

### 适用场景
- 电商平台的买家评论分类路由
- SaaS 产品的用户反馈分发
- 餐饮/酒店的在线评价处理
- App Store / 应用市场评论分拣

### 不适用场景

| 场景 | 本质原因 | 替代方案 |
|---|---|---|
| **评论分类超过3类** | 当前仅支持正面/售后/物流三类 | 扩展 Categorize 节点的分类选项 |
| **需要自动回复评论** | 只有路由发邮件，无生成回复功能 | 增加 LLM 节点生成回复内容 |
| **需要情感分析详情** | 只输出分类结果，无情感强度分析 | 增加 Agent 节点输出详细情感报告 |
| **高频自动化接入** | 当前是对话模式，需手动输入评论 | 通过 API 集成对接平台自动推送 |
| **需要评论数据统计** | 无数据持久化，无统计仪表盘 | 接入数据库 + BI 工具 |

## 四、产品成熟度评估

| 评估维度 | 评分 | 说明 |
|---|---|---|
| **需求清晰度** | ★★★★★ | 场景明确，路由逻辑清晰 |
| **分类设计合理性** | ★★★★☆ | 两级分类合理，但当前类别过少，实际场景不够用 |
| **开箱即用性** | ★★☆☆☆ | 邮件凭证（SMTP、收件人）需手动配置，不配则完全无法运行 |
| **可扩展性** | ★★★★☆ | Categorize 节点扩展方便，新增类别成本低 |
| **错误处理** | ★★☆☆☆ | 邮件发送失败时无重试机制，无告警通知 |
| **数据可追溯性** | ★★★☆☆ | 仅输出成功/失败状态，无历史记录 |

## 五、迭代方向建议

**短期（低成本，高价值）**

1. **扩展分类体系**：负面评论增加更多子类（产品质量、包装破损、描述不符、态度问题），适配更真实的业务场景
2. **增加自动回复生成**：分类完成后，用 LLM 为每类评论生成标准化的初步回复草稿，直接抄送给客服人员
3. **邮件内容丰富化**：邮件正文除原始评论外，增加 AI 提炼的问题摘要和建议优先级

**中期（功能增强）**

4. **评论数据持久化**：接入数据库节点，每条评论的分类结果自动写入，支持后续统计分析
5. **情感强度评分**：在分类的同时输出情感强度（1-5分），让运营团队优先处理高强度负面评论
6. **批量处理模式**：支持一次上传多条评论（CSV/Excel），Iteration 容器批量处理

**长期（产品升级）**

7. **平台 API 对接**：直接接入淘宝/京东/美团等平台的评论 API，实现全自动化
8. **统计报表仪表盘**：按时间、类别、情感强度自动生成周报/月报，发送给管理层
