# Choose Your Knowledge Base Agent — 开发者视角

---

## 一、节点类型全景

| 节点类型 | 实例 | 作用 |
|---|---|---|
| `Begin` | begin | 提供下拉选择（知识库选择）+ 接收问题 |
| `Agent` | 问答 Agent | 根据选择的知识库进行 Retrieval 检索 |
| `Message` | 输出节点 | 展示回答 |

---

## 二、关键机制：Begin 节点的下拉参数

```json
begin 节点输入参数：
{
  "type": "select",          // 下拉选择类型（区别于 line 文本输入）
  "name": "knowledge_base",
  "options": [
    {"label": "HR 政策文档", "value": "kb_id_001"},
    {"label": "技术文档库",  "value": "kb_id_002"},
    {"label": "产品手册",    "value": "kb_id_003"}
  ],
  "required": true
}
```

用户选择后，`begin@knowledge_base` 的值为对应知识库的 ID，传递给下游 Agent 节点，Agent 使用该 ID 动态绑定 Retrieval 工具的知识库目标。

---

## 三、与 choose_your_knowledge_base_workflow 的区别

| 对比维度 | Agent 版（本模板） | Workflow 版 |
|---|---|---|
| Retrieval 位置 | Agent 内置工具 | 独立节点 |
| 调用控制 | Agent 自主决定何时检索 | 执行引擎强制调用 |
| 灵活性 | 高（可多次检索） | 低（固定一次） |
| 可预测性 | 低（Agent 行为灵活） | 高（流程固定） |

**选择建议**：问题复杂、需要多轮检索 → Agent 版；流程简单、要求稳定可控 → Workflow 版。

---

## 四、落地配置

```
1. 预先在 RAGFlow 建好各个知识库，记录各知识库的 ID

2. 在 Begin 节点的下拉参数中配置：
   - label：用户看到的知识库名称（友好命名）
   - value：对应知识库的 RAGFlow KB ID

3. 在 Agent 节点的 Retrieval 工具中：
   配置为使用 {begin@knowledge_base} 动态选择知识库
   （而非静态绑定固定知识库 ID）

4. 测试：分别选择不同知识库，提同一个问题
   验证 Agent 确实在不同知识库中检索
```
