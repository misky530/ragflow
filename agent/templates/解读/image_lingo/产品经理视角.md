# Image Lingo — 产品经理视角

---

## 一、目标用户与核心痛点

| 用户类型 | 核心需求 | 当前痛点 |
|---|---|---|
| 电商运营 | 批量生成商品图片的文案描述 | 人工为每张图写描述耗时，风格不统一 |
| 内容创作者 | 理解图片内容，辅助创作 | 需要手动描述图片再交给 AI 处理，流程繁琐 |
| 质检/审核人员 | 自动识别图片中的问题或违规内容 | 人工审图速度慢，漏检率高 |
| 教育/培训机构 | 分析图表、试卷截图中的内容 | 图片内容无法直接输入传统文本 AI |
| 医疗辅助 | 理解医学影像的文字描述 | 需要专业知识，人力成本高 |

**核心价值主张**：让 AI 真正"看懂"图片——不只是识别文字（OCR），而是理解图片的语义内容，并据此回答问题或生成洞察。

## 二、功能设计的 PM 逻辑

### 2.1 VLM 模型选型 — qwen-vl-plus 的定位

模板使用 `qwen-vl-plus`（通义千问视觉语言版），这个选型的含义：
- **"vl"**：Vision-Language，多模态模型，同时处理图像和文本
- **"plus"**：中等能力版本，比 max 版本便宜，适合通用场景

**PM 洞察**：选择 plus 而非 max 是成本与能力的权衡。对于大多数图文理解场景（商品图描述、图表分析、文档截图），plus 级别已经足够。只有复杂医疗影像、精细艺术分析等场景才需要更高端的模型。

### 2.2 `visual_files_var=sys.files` — 图片传入的关键机制

这是图文模板与纯文本模板最关键的区别：Agent 节点通过 `visual_files_var` 参数指定图片来源变量，将 `sys.files` 中的图片文件直接传给 VLM 模型。

**PM 洞察**：这个设计意味着用户可以在对话中随时上传图片，无需额外的"图片上传入口"——聊天界面即是上传入口，体验自然流畅。

## 三、产品边界

### 适用场景
- 商品图片自动描述生成
- 文档/表格截图内容提取
- 图表数据分析和解读
- 图片内容问答（"这张图里有什么？"）
- 界面/设计稿的文字描述

### 不适用场景

| 场景 | 原因 | 替代方案 |
|---|---|---|
| **批量图片处理** | 对话模式需逐张上传 | 配合 Iteration 节点批量处理 |
| **精准 OCR 文字提取** | VLM 的文字识别不如专用 OCR 精准 | RAGFlow 内置文档解析（deepdoc） |
| **医疗影像诊断** | 需要专业医疗模型，通用 VLM 不适合 | 使用专业医疗 VLM + 人工复核 |
| **实时视频分析** | 不支持视频输入，只支持静态图片 | 需要其他专用工具 |

## 四、产品成熟度评估

| 评估维度 | 评分 | 说明 |
|---|---|---|
| **需求真实性** | ★★★★★ | 图文理解是高频真实需求 |
| **架构简洁性** | ★★★★★ | 单 Agent + VLM，极简 |
| **开箱即用性** | ★★★☆☆ | 需配置 Tongyi-Qianwen API Key，且 vl 模型需单独开通 |
| **模型扩展性** | ★★★☆☆ | 当前绑定 qwen-vl，换模型需手动修改 |
| **场景覆盖广度** | ★★★★☆ | 通用图文理解，覆盖多数日常场景 |

## 五、迭代方向建议

1. **批量图片处理**：配合 Iteration 节点，支持一次上传多张图片批量分析（如批量商品图生成描述）
2. **图文混合知识库**：将图片理解结果存入知识库，支持后续基于图片内容的检索
3. **输出格式定制**：根据场景定制输出（电商文案格式/学术描述格式/质检报告格式）
4. **多模型支持**：增加 Claude Vision / GPT-4V 作为备选模型
