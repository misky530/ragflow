# Image Lingo — 开发者视角

---

## 一、节点类型全景

| 节点类型 | 实例 | 作用 |
|---|---|---|
| `Begin` | begin | 对话入口，接收用户问题和图片上传 |
| `Agent` | 多模态 Agent | 使用 VLM 理解图片 + 文本，生成回答 |
| `Message` | 输出节点 | 展示回答 |

---

## 二、多模态数据流

```
begin
  ├── sys.query（用户文字问题）
  └── sys.files（用户上传的图片文件）
          │
          ↓
Agent（qwen-vl-plus@Tongyi-Qianwen）
  关键配置：visual_files_var = "sys.files"
            ↑
            这个参数告诉 Agent：
            将 sys.files 中的文件作为视觉输入传入 VLM

  LLM 接收：
    - 文本 prompt（来自 sys.query）
    - 图片数据（来自 sys.files，通过 visual_files_var 传入）

  处理：VLM 同时理解文本和图片，生成回答
  输出：@content
          │
          ↓
Message → 用户界面
```

---

## 三、关键配置参数

### `visual_files_var` — 图文模板的核心参数

```json
"visual_files_var": "sys.files"
```

这个参数是区分**图文 Agent** 和**纯文本 Agent** 的关键配置：
- 设置后：Agent 会将指定变量中的文件作为视觉输入传给 VLM
- 不设置：Agent 只处理文本输入

**支持的图片格式**：通常为 JPG、PNG、WebP，具体取决于所用 VLM 的限制。

### 模型要求

必须使用支持视觉输入的模型（VLM），普通文本模型无法处理图片输入：

| 模型类别 | 示例 | 是否支持 |
|---|---|---|
| 视觉语言模型（VLM） | qwen-vl-plus, GPT-4V, Claude-3-vision | ✅ |
| 纯文本模型 | deepseek-chat, qwen-max | ❌ |

---

## 四、已知局限

| 局限 | 技术原因 | 影响 |
|---|---|---|
| 单张/少量图片 | 对话模式，每次交互上传 | 批量处理需配合 Iteration |
| 图片大小限制 | VLM API 对图片大小有限制（通常 ≤20MB） | 超大图片需压缩后上传 |
| 无图片持久化 | 图片仅在当前对话中有效 | 无法基于历史图片进行对比分析 |
| 模型单一 | 绑定 qwen-vl-plus | 需要手动修改才能换用其他 VLM |

---

## 五、可扩展点

```
批量图片分析
  在 Agent 前增加 Iteration 节点
  遍历 sys.files 中的每张图片
  Agent 逐张分析，输出结构化描述

图文知识库构建
  Agent 分析图片 → 输出文字描述 → 写入知识库
  后续可用文字检索相关图片内容

多步图片处理
  Step1: 图片分类 Agent（判断图片类型）
  Step2: 专用分析 Agent（根据类型调用不同 prompt）
  例：电商图 → 生成商品描述；证件图 → 提取关键信息
```

## 六、落地配置

```
1. 开通 Tongyi-Qianwen 的 qwen-vl-plus 模型权限
   （vl 系列需要单独申请，与文本模型权限不同）

2. 在 RAGFlow 模型提供商配置中确认 qwen-vl-plus 可用

3. 导入模板，验证 Agent 节点的：
   - 模型绑定：qwen-vl-plus@Tongyi-Qianwen
   - visual_files_var：sys.files

4. 测试：上传一张图片，提问"描述这张图片的内容"
   验证模型是否正确理解图片
```
