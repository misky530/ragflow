# Web Search Assistant — 开发者视角

---

## 一、节点类型全景

| 节点类型 | 实例 | 作用 |
|---|---|---|
| `Begin` | begin | 对话入口 |
| `Agent` | Question Refinement | 将用户问题优化为搜索友好的表述 |
| `Agent` + Tool | Web Search Agent | 调用 TavilySearch 检索公开网络 |
| `Retrieval` | 内部知识库 | 检索 RAGFlow 知识库 |
| `Agent` | Answer Organizer | 整合双路信息，生成最终回答 |
| `Message` | 输出节点 | 展示整合后的回答 |

---

## 二、数据流分析

```
begin
  └── sys.query（用户原始问题）
          │
          ↓
Question Refinement Agent
  输入：sys.query
  任务：口语化问题 → 结构化搜索查询
  输出：@refined_query（优化后的查询词）
          │
          ├───────────────────────┐
          ↓                       ↓
Web Search Agent            Retrieval（知识库）
  输入：@refined_query         输入：@refined_query
  工具：TavilySearch           检索：内部知识库
  输出：@web_content            输出：@kb_content
（并行执行）
          │                       │
          └──────────┬────────────┘
                     ↓
            Answer Organizer Agent
            输入：
              - sys.query（原始问题）
              - @web_content（网络检索结果）
              - @kb_content（知识库检索结果）
            任务：
              1. 判断两路信息是否一致
              2. 优先使用知识库权威内容
              3. 用网络内容补充/验证
              4. 整合成连贯的回答
            输出：@final_answer
                     │
                     ↓
            Message → 用户界面
```

## 三、Question Refinement 的价值

Question Refinement Agent 接收原始问题后，做以下转化：

| 原始问题（用户输入） | 优化后（用于搜索） |
|---|---|
| "那个新的数据安全规定是什么" | "2024年数据安全法规最新规定" |
| "我们的退款政策" | "企业退款政策 用户申请流程" |
| "为什么最近响应这么慢" | "系统响应延迟 性能问题 排查" |

优化后的 `@refined_query` 同时用于 Web Search 和 Retrieval，确保两路搜索使用相同的、质量更高的查询词。

## 四、双路整合的关键 Prompt 设计

Answer Organizer 的 system prompt 是整个模板质量的关键，建议包含：

```
当内部知识库与网络信息一致时：
  优先引用知识库内容，网络信息作为验证

当内部知识库与网络信息不一致时：
  明确说明差异："内部规定为X，最新网络信息显示Y，
  建议以内部规定为准，或联系相关部门确认"

当知识库无相关内容时：
  仅使用网络信息，并注明"以下信息来自公开网络，
  如与内部规定有出入，请以内部文档为准"

回答格式：
  明确标注每段信息的来源（[内部文档] 或 [网络来源]）
```

## 五、与 technical_docs_qa 的架构差异

| 维度 | technical_docs_qa | web_search_assistant |
|---|---|---|
| 信息来源 | 仅内部知识库 | 内部知识库 + 公开网络 |
| LLM 调用次数 | 1次 | 3次（Refinement + Search + Organizer）|
| Tavily 费用 | 无 | 有（每次搜索） |
| 时效性 | 取决于知识库更新频率 | 实时网络信息 |
| 回答权威性 | 高（内部文档） | 中（混合来源，需要判断） |

## 六、落地配置

```
1. 建立内部知识库（同 technical_docs_qa）

2. 配置 Tavily API Key（用于 Web Search Agent）

3. 配置 Answer Organizer 的 system prompt（关键！）
   定义信息优先级和冲突处理规则

4. 测试三种场景：
   a. 知识库有答案、网络也有 → 验证整合效果
   b. 知识库有答案、网络信息矛盾 → 验证冲突处理
   c. 知识库无答案 → 验证降级到纯网络信息
```
