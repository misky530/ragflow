# Web Search Assistant — 产品经理视角

---

## 一、目标用户与核心痛点

| 用户类型 | 核心需求 | 当前痛点 |
|---|---|---|
| 客服/支持团队 | 回答用户问题时需要内部规范+最新政策 | 内部知识库有时过时，但网络信息又不够权威 |
| 企业研究员 | 结合公司内部报告和最新公开信息做分析 | 两类信息分散，需要手动整合 |
| 技术支持工程师 | 查内部文档的同时查最新官方文档/社区 | 内外部文档经常不同步 |

**核心价值主张**：内部文档的权威性 + 公开网络的时效性，两者兼得——不再需要在内网知识库和搜索引擎之间切换。

---

## 二、功能设计的 PM 逻辑

### 2.1 Question Refinement — 为什么要先优化问题？

用户的原始问题往往口语化、不够精确，直接拿去搜索效果差。第一个 Agent 的任务是**将口语化问题转化为搜索友好的标准表述**。

**PM 洞察**：这是搜索类产品的成熟实践。用户说"那个新出的隐私规定是啥意思"，系统转化为"2024年数据隐私法规最新要求"再去搜索，质量完全不同。

### 2.2 并行双源 — 内外部知识互补而非替代

| 数据源 | 优势 | 劣势 |
|---|---|---|
| **内部知识库** | 权威、准确、符合公司规范 | 可能过时，覆盖范围有限 |
| **公开网络** | 时效性强，覆盖全面 | 信息质量参差不齐，可能与内部规范冲突 |

并行检索后由 Answer Organizer 整合，优先使用内部知识库内容，网络内容作为补充或验证。

### 2.3 Answer Organizer — 整合的核心挑战

两路信息可能存在**矛盾**（内部规定与最新政策不一致），Answer Organizer 需要：
1. 识别两路信息是否一致
2. 冲突时优先内部权威文档，并提示网络信息供参考
3. 明确标注每条信息来源

## 三、产品边界

### 适用场景
- 客服知识库 + 最新政策的混合查询
- 企业内部文档 + 行业最新动态的结合分析
- 技术文档 + 社区/官方最新更新的同步查询

### 不适用场景

| 场景 | 替代方案 |
|---|---|
| 只有内部文档，无需联网 | `technical_docs_qa`（更简单，成本更低） |
| 只需联网，无内部知识库 | `deep_research`（更深度的网络研究） |
| 需要极高信息准确性 | 人工核验，不能依赖 AI 混合输出 |

## 四、产品成熟度评估

| 评估维度 | 评分 | 说明 |
|---|---|---|
| **架构设计合理性** | ★★★★★ | 问题优化+并行双源+整合，是标准的混合搜索架构 |
| **开箱即用性** | ★★★☆☆ | 需要 Tavily API + 知识库，配置成本中等 |
| **信息冲突处理** | ★★★☆☆ | 依赖 Answer Organizer 的 prompt 质量 |
| **成本** | ★★★☆☆ | 比纯 RAG 高（额外 Tavily 费用 + 多个 LLM 调用） |

---

## 五、迭代方向建议

1. **来源标注**：回答中明确区分"来自内部文档"和"来自网络"的内容
2. **冲突检测**：当内外部信息矛盾时，主动提示用户"内外部信息不一致，请人工核实"
3. **信息时效标注**：网络来源显示抓取时间，内部文档显示最后更新时间
