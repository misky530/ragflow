# Web Search Assistant — 业务视角

---

## 一、ROI 与定位

```
对比 technical_docs_qa（纯知识库）：
  额外成本：Tavily API（每次搜索约 $0.005）+ 更多 LLM 调用
  额外价值：实时网络信息，知识库过时问题得到缓解

适用场景判断：
  知识库更新频率高（每周）→ 用 technical_docs_qa 即可
  知识库更新慢（按季度）或外部政策/信息变化快 → 用 web_search_assistant
```

---

## 二、目标客户

| 客户类型 | 为什么适合 |
|---|---|
| **合规/法务部门** | 内部政策 + 最新法规同步查询，规避合规风险 |
| **客服团队** | 内部产品知识 + 最新公告同步回答用户问题 |
| **研究/情报团队** | 内部分析报告 + 最新外部动态的混合检索 |

---

## 三、销售定位

这个模板应该定位为 `technical_docs_qa` 的**升级版**：

> "基础版只查你们的内部文档。升级版同时查内部文档和最新网络信息，当内外部信息不一致时还会提醒你。对于需要同时关注内部规范和外部动态的团队，升级版的价值更大。"

---

## 四、一句话总结

> Web Search Assistant 是**内外部知识融合**的标准架构，适合知识库内容无法保持实时更新的场景。相比纯 RAG 方案增加了 Tavily 成本，但解决了知识库过时的核心痛点。
