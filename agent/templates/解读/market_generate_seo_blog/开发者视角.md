# Market Generate SEO Blog — 开发者视角

---

## 一、架构概览

```
begin
  ↓
Parse & Keyword Agent（解析意图+关键词，deepseek-chat，无工具）
  ↓
Outline Agent（生成大纲，deepseek-chat + TavilySearch）
  ↓
Body Agent（撰写正文，deepseek-chat + TavilySearch）
  ↓
Editor Agent（SEO 审校，deepseek-chat）
  ↓
Message（输出完整博客）
```

**架构类型**：4 个独立串行 Agent 节点，线性流水线

---

## 二、节点详解

### Parse & Keyword Agent（节点 1）
- `llm_id`: `deepseek-chat@DeepSeek`
- `temperature`: 0.2，`max_rounds`: 1
- **无工具**（纯 LLM 推理）
- **输入**：`sys.query`
- **输出**：Writing Type、Target Audience、User Intent Summary、3~5 个长尾关键词

### Outline Agent（节点 2）
- `llm_id`: `deepseek-chat@DeepSeek`
- `temperature`: 0.5，`max_rounds`: 3
- **工具**：TavilySearch（可选调用，搜索结构参考）
- **输入**：`{Agent:ClearRabbitsScream@content}`（Parse Agent 输出）
- **输出**：H2/H3 大纲 + 每节关键词建议

### Body Agent（节点 3）
- `llm_id`: `deepseek-chat@DeepSeek`
- `max_rounds`: 5（正文生成，轮次最多）
- **工具**：TavilySearch（补充事实和案例）
- **输入**：Parse Agent 输出 + Outline Agent 输出
- **输出**：完整正文草稿

### Editor Agent（节点 4）
- `llm_id`: `deepseek-chat@DeepSeek`
- **无工具**（纯语言优化）
- **输入**：Body Agent 输出
- **输出**：润色后全文 + meta title + meta description

---

## 三、与 generate_SEO_blog 的技术差异

| 维度 | generate_SEO_blog | market_generate_seo_blog |
|---|---|---|
| 架构 | 主控 Agent + 3 嵌套子 Agent | 4 独立串行 Agent 节点 |
| 节点数量 | 1 主控 + 3 工具 Agent | 4 个平级 Agent 节点 |
| 数据传递 | 主控 Agent 统一管理上下文 | 通过 `{AgentId@content}` 变量传递 |
| 调试难度 | 较难（嵌套调用链） | 较易（每节点独立可观测） |
| 灵活性 | 高（主控可动态调整） | 低（流程固定） |

**技术洞察**：独立串行节点的数据传递通过 `{Agent:ID@content}` 变量引用实现——Body Agent 同时接收 Parse Agent 和 Outline Agent 的输出，用于生成上下文完整的正文。

---

## 四、部署要点

```
1. 4 个节点全部使用 deepseek-chat，配置一个 DeepSeek API Key 即可
2. TavilySearch Key 需要在 Outline Agent 和 Body Agent 中各配置一次
3. Body Agent max_rounds=5，是 token 消耗最大的节点（完整正文生成）
4. 变量引用格式：{Agent:ClearRabbitsScream@content}（注意 Agent ID 完整格式）
5. 线性流程无分支，调试时可逐节点输出验证
```
