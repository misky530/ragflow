# Customer Support — 产品经理视角

---

## 一、与 customer_service 的核心差异

两个模板解决的是**同一个业务问题**，用户体验基本相同，区别在内部实现：

| 维度 | customer_service | customer_support |
|---|---|---|
| 分支汇合方式 | VariableAggregator 显式汇合 | 各分支直通 Message（隐式汇合） |
| 架构透明度 | 高（数据流清晰） | 中（依赖框架内部机制） |
| 扩展性 | 极高（新增分支只需加 Agent + 连接 VariableAggregator） | 高（新增分支直连 Message） |
| canvas_type | Agent | Customer Support（垂直分类） |

**PM 洞察**：`customer_support` 的 `canvas_type = "Customer Support"` 是 RAGFlow 针对客服垂直场景的**专属分类标签**，会在模板库的客服分类下展示。这说明 RAGFlow 有意将客服场景作为重点垂直方向运营。

---

## 二、何时选哪个版本？

| 场景 | 推荐版本 | 原因 |
|---|---|---|
| 需要清晰的数据流审计 | customer_service | VariableAggregator 让数据流更透明 |
| 快速搭建客服原型 | customer_support | 更简洁，少一个节点 |
| 团队对 RAGFlow 节点熟悉 | customer_service | VariableAggregator 模式更规范 |
| 从模板库选择时 | customer_support | 在客服垂直分类下更容易被发现 |

---

## 三、产品成熟度评估

与 customer_service 基本相同，参阅 [../customer_service/产品经理视角.md](../customer_service/产品经理视角.md)。

`customer_support` 略胜在：垂直分类标签让目标用户更容易发现它。
