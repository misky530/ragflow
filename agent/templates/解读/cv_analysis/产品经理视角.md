## 一、目标用户与核心痛点

模板欢迎语直接定义了使用者：**HR 招聘团队**。核心场景是：有一份 JD，有一批简历，需要快速筛出匹配候选人。

| 用户类型 | 核心需求 | 当前痛点 |
|---|---|---|
| HR 招聘专员 | 快速筛选大量简历，找出匹配 JD 的候选人 | 人工阅读耗时，评判标准不统一 |
| HR BP | 向业务方提供候选人对比报告 | 简历格式五花八门，难以横向比较 |
| 猎头/招聘外包 | 批量处理多个职位的候选人 | 重复劳动多，效率低 |
| 小型企业 HR | 没有专职分析师，需要工具辅助 | 缺乏资源搭建专业筛选流程 |

**核心价值主张**：把 HR 从"逐份阅读简历"的重复劳动中解放出来，用统一标准批量输出结构化评估报告。

## 二、功能设计的 PM 逻辑

### 2.1 结构化信息提取 — 标准化是核心产品价值

系统 prompt 要求从每份简历提取 **6 个固定字段**：

| 字段 | 提取内容 | 产品价值 |
|---|---|---|
| **姓名** | 不含称谓的全名 | 消除格式差异，统一显示 |
| **联系方式** | 手机/邮件标准格式 | HR 直接可用，无需二次处理 |
| **最高学历** | 最近就读院校 | 快速定位教育背景 |
| **工作年限** | 数字（年数或毕业年份） | 可量化比较，支持过滤 |
| **所在城市** | 仅城市名 | 判断是否需要异地 relocation |
| **JD 匹配分析** | 0-10 分 + 匹配/差距说明 | 核心决策依据 |

**PM 洞察**：这 6 个字段对应 HR 初筛的**必要信息集合**。简历格式千变万化，产品价值在于把非结构化文本转化为**可对比的结构化数据**。

### 2.2 JD 匹配评分系统 — 简单但有效的决策支持

```
Score: [X/10]
Matching Analysis:
- 主要匹配点（经验/技能/学历）
- 差距或不匹配项
（内容长度限制：30-50字）
```

**PM 洞察**：
1. **0-10 分制**比百分制直观，HR 无需换算
2. **匹配 + 差距并列展示**，给 HR 提供判断依据，而非强迫接受 AI 结论
3. **30-50 字内容限制**强制 AI 给出精炼判断，避免模板式废话

### 2.3 输出格式规范 — 细节决定体验

- **不允许子标题**：纯文本适合聊天界面直接显示
- **简历之间段落分隔**：批量处理时结果清晰隔开
- **统一中文输出**：强制中文

**PM 洞察**："强制中文"是**产品定位声明**，不是技术限制。首要目标市场是国内 HR 场景。如果需要国际化，这是第一个需要修改的地方。

### 2.4 MCP 扩展能力 — 预留的产品增长点

Canvas 注释中提到了 **Google Sheet MCP** 集成：
- 评估结果可通过 MCP 自动写入 Google Sheets
- 实现候选人数据的持久化和团队共享

**PM 洞察**：这是**产品路线图信号**。当前是最简单的 MVP，但团队已预见到 HR 需要导出、归档、共享结果的需求，只是尚未实现。

## 三、产品边界

### 不适用场景

| 场景 | 本质原因 | 替代方案 |
|---|---|---|
| **图片型 PDF / 扫描件** | 无 OCR，假设文本已可读 | 先经过 RAGFlow 文档解析预处理 |
| **自定义评分权重** | 评分维度固定，无权重配置 | 修改 system prompt 增加权重说明 |
| **需要人工审核介入** | 全自动流程，无审核节点 | 增加 Categorize 节点分流 |
| **高保密岗位简历** | 简历内容上传至第三方 LLM API | 私有化部署 + 本地模型 |
| **结果需要持久化** | 仅输出到聊天，刷新后消失 | 接入 Google Sheets MCP |
| **多语言混合批处理** | 输出强制中文，非中文 HR 用不了 | 修改 system prompt 语言设定 |

**最大隐性限制**：模板假设上传的简历文件已经是可提取的文本内容。现实中大量简历是图片型 PDF 或复杂 Word，这是实际部署时第一个会踩的坑。

## 四、产品成熟度评估

| 评估维度 | 评分 | 说明 |
|---|---|---|
| **需求清晰度** | ★★★★★ | HR 简历筛选场景明确，痛点真实 |
| **架构简洁性** | ★★★★★ | Iteration + 单 Agent，轻量易维护 |
| **开箱即用性** | ★★★★☆ | 仅需 DeepSeek API，门槛极低 |
| **输出质量稳定性** | ★★★★☆ | temperature=0.1 保证一致性，但无验证机制 |
| **数据持久化** | ★★☆☆☆ | 结果仅在聊天界面，无导出能力 |
| **国际化就绪度** | ★★☆☆☆ | 强制中文，非中文市场需修改 |
| **数据隐私保障** | ★★☆☆☆ | 无内置脱敏机制，企业部署需额外配置 |

## 五、迭代方向建议

**短期（低成本，高价值）**

1. **候选人序号标注**：在 Agent user prompt 中使用 `IterationItem@index`，让每位候选人自动编号，HR 便于对照原始文件
2. **输出语言配置化**：将"always use Chinese"改为跟随用户界面语言，解锁国际市场
3. **结果导出**：接入 Google Sheets MCP 或提供 CSV 下载

**中期（功能增强）**

4. **候选人排序汇总**：Iteration 后增加汇总 Agent，按分数排序输出 Top N 推荐列表
5. **自定义评分维度**：begin 节点增加"技能权重"输入项，例如"技术栈权重60%，行业经验权重40%"
6. **人工审核分流**：高分自动推进，低分自动过滤，中间分数进入人工复核队列

**长期（产品升级）**

7. **ATS 系统集成**：对接猎聘、Boss 直聘、Workday，实现简历自动同步
8. **面试问题生成**：基于简历与 JD 的差距自动生成针对性面试问题
9. **候选人数据库**：多次使用后积累岗位候选人画像，支持历史候选人二次匹配
