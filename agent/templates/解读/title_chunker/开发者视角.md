# Title Chunker — 开发者视角

---

## 一、架构概览

```
File
  ↓
Parser:HipSignsRhyme（pdf→json, word→json, text→text）
  ↓
HierarchicalMerger:BusyPoetsSearch（按 H1~H4 标题切分，hierarchy=3）
  ↓
Tokenizer:NeatRadiosEnd（fields="text"，embedding+full_text）
```

**canvas_category**: `"dataflow_canvas"`
**无任何 LLM 节点**：纯规则处理流水线

---

## 二、关键组件：HierarchicalMerger

```json
{
  "component_name": "HierarchicalMerger",
  "params": {
    "hierarchy": 3,
    "levels": [
      ["^#[^#]"],    // Level 0: H1，匹配 "# 标题"
      ["^##[^#]"],   // Level 1: H2，匹配 "## 标题"
      ["^###[^#]"],  // Level 2: H3，匹配 "### 标题"
      ["^####[^#]"]  // Level 3: H4，匹配 "#### 标题"
    ]
  }
}
```

### 正则说明

| 正则 | 匹配 | 不匹配 |
|---|---|---|
| `^#[^#]` | `# H1标题` | `## H2标题`、`### H3标题` |
| `^##[^#]` | `## H2标题` | `### H3标题` |
| `^###[^#]` | `### H3标题` | `#### H4标题` |
| `^####[^#]` | `#### H4标题` | — |

**`[^#]` 的作用**：确保匹配的 `#` 后面不是另一个 `#`，避免 `## H2` 被 `^#[^#]` 匹配。

### `hierarchy=3` 的含义

`hierarchy` 控制合并深度——值为 3 表示将 H4 级别的内容合并到层级树中深度为 3 的父节点。简单理解：内容会按标题层级聚合，形成语义完整的章节切片。

## 三、Parser 输出格式

```json
// Title Chunker 中 Parser 配置
{
  "pdf": {"output_format": "json"},   // 保留结构信息（块位置、标题层级）
  "word": {"output_format": "json"},  // 保留 Word 的标题样式信息
  "text&markdown": {"output_format": "text"}  // 文本/Markdown 直接传递
}
```

**注意**：PDF 和 Word 输出为 `json`（保留文档结构），这对 HierarchicalMerger 识别标题至关重要。若 PDF 无法识别标题层级，HierarchicalMerger 可能退化为单块输出。

---

## 四、Tokenizer 配置

```json
{
  "fields": "text",
  "search_method": ["embedding", "full_text"],
  "filename_embd_weight": 0.1
}
```

与 advanced_ingestion_pipeline 相同，索引原文（非摘要）。但切片已经是按章节切分的语义完整内容，所以原文索引质量更高。

## 五、与其他摄取模板对比

| 维度 | title_chunker | chunk_summary | advanced |
|---|---|---|---|
| 切片策略 | 按标题结构 | 固定 token 数 | 固定 token 数 |
| LLM 节点 | 无 | 1（summary） | 4 |
| 增强字段 | 无 | summary | summary/keywords/questions/metadata |
| 索引字段 | text | summary | text |
| 摄取成本 | 最低 | 中 | 最高 |
| 适用前提 | 文档有标题结构 | 文档有噪声 | 需要多维检索 |

## 六、部署要点

```
1. 无需 LLM API Key（纯规则处理）
2. Parser 输出格式必须为 json（PDF/Word）才能保留标题结构
3. 文档必须有符合 Markdown 规范的标题（H1~H4）
4. 测试方法：先确认文档解析后的 json 输出中是否包含标题信息
5. 若文档标题使用非 Markdown 格式（如 Word 标题样式），Parser 需要正确转换
6. 中文标题支持：正则 "^#[^#]" 对中文标题有效（如 "# 一、概述"）
```

---

## 七、边界情况

```
情况 1：文档无标题
  → HierarchicalMerger 无切分点，可能输出单个大块
  → 建议：改用 Splitter + chunk_summary

情况 2：嵌套标题过深（H5 及以上）
  → levels 只配置到 H4，H5+ 会被归入 H4 切片
  → 基本可接受

情况 3：标题紧密（每 50 字一个 H2）
  → 会产生大量小切片，可能影响检索质量
  → 考虑调整 hierarchy 值
```
