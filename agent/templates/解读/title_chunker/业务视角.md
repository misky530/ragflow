# Title Chunker — 业务视角

---

## 一、核心价值

```
问题：文档按页数/字数机械切割，章节被截断
  症状：用户问"第三章讲什么"，AI 拼凑的答案来自三个不完整切片

Title Chunker 的解法：
  文档按章节标题切片 → 每片 = 完整章节
  用户问"第三章"→ 直接召回"第三章"整个切片
  
成本：无 LLM 调用，几乎零额外成本
速度：比其他 Ingestion Pipeline 模板快 4~10 倍
```

---

## 二、目标客户

| 客户类型 | 适合程度 | 说明 |
|---|---|---|
| **技术文档知识库** | ★★★★★ | API 文档/用户手册章节结构天然清晰 |
| **法律合规文档库** | ★★★★★ | 法规条款按章节编号，完美契合 |
| **企业规章制度库** | ★★★★★ | 管理制度有章节结构，逐章可检索 |
| **学术论文库** | ★★★★☆ | 论文有标准章节，但 PDF 解析质量影响效果 |
| **新闻/博客文章** | ★★☆☆☆ | 文章无明确标题层级，效果差 |

---

## 三、销售话术

**对知识库管理员**：
> "你们的文档都有章节结构吗？比如产品手册有'安装/配置/故障排除'这些章节？Title Chunker 可以按这些章节切分，每个 AI 查询都直接命中完整的章节内容——而且不需要调用 AI 生成摘要，成本比其他方案低得多。"

---

## 四、与其他方案的选择建议

**根据文档特点选方案**：

```
文档有清晰标题结构？
  是 → Title Chunker（零 LLM 成本，语义完整）
  否 → 文档有噪声/长段落？
        是 → Chunk Summary（摘要降噪）
        否 → 需要多维度检索？
              是 → Advanced Ingestion Pipeline
              否 → 基础摄取（无额外成本）
```

---

## 五、一句话总结

> Title Chunker 是**结构化文档知识库的零成本增强方案**：HierarchicalMerger 按 H1~H4 标题切分，保证每个检索单元是语义完整的章节，无需 LLM 调用、成本最低、速度最快，是有标题结构的技术文档/法规文档的首选摄取方案。
