# E-commerce Customer Service Workflow — 开发者视角

---

## 一、数据流分析

```
begin → sys.query
          │
          ↓
Categorize（订单 / 产品 / 其他）
          │
    ┌─────┼──────────┐
    ↓     ↓          ↓
 订单分支 产品分支   其他分支
    │       │          │
Retrieval Retrieval  Retrieval
（订单库）（产品库）  （通用库）
    │       │          │
  Agent   Agent      Agent
    │       │          │
    └───────┴──────────┘
              │
           Message
```

---

## 二、独立 Retrieval 节点的优势

每个分支有自己的 Retrieval 节点，可以独立配置：

```
订单分支 Retrieval：
  knowledge_base: 订单知识库
  retrieval_mode: 全文检索（订单号等关键词精确匹配）
  top_k: 3

产品分支 Retrieval：
  knowledge_base: 产品知识库
  retrieval_mode: 向量检索（产品语义理解）
  top_k: 5
  rerank: true（产品查询需要高精准度）

其他分支 Retrieval：
  knowledge_base: 通用 FAQ 库
  retrieval_mode: 混合检索
  top_k: 3
```

这种独立配置是 customer_service/support（Agent 内置 Retrieval）做不到的。

## 三、落地配置

```
1. 建立3个知识库：
   - 订单知识库：退款政策、物流规则、订单处理流程
   - 产品知识库：产品规格、参数、FAQ
   - 通用知识库：会员政策、品牌介绍等

2. 配置 Categorize 分类（3类 + 示例）

3. 各分支 Retrieval 节点绑定对应知识库
   配置不同的检索参数

4. 各分支 Agent 配置专业 system prompt
   订单 Agent：政策准确、流程清晰
   产品 Agent：参数详细、规格精准
   通用 Agent：友好、万能兜底

5. 测试边界：
   "我的这个产品的订单在哪里？" 
   → 应路由到订单还是产品？（设计决策）
```
