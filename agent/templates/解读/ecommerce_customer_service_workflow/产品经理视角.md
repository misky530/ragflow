# E-commerce Customer Service Workflow — 产品经理视角

---

## 一、目标用户与核心痛点

专为**电商场景**设计，三类核心意图对应电商客服的实际业务：

| 意图类别 | 典型问题 | 对应知识库 |
|---|---|---|
| **订单相关** | 我的订单到哪了？怎么退款？发货多久？ | 订单政策、物流规则、退款流程 |
| **产品相关** | 这款产品有没有 XXL 码？支持哪些颜色？ | 产品参数、库存信息、规格说明 |
| **其他** | 你们有没有会员？积分怎么用？ | 通用 FAQ、会员政策 |

**核心价值主张**：把电商客服场景标准化——订单问题找订单库，产品问题找产品库，不再用一个大知识库"通吃"导致回答不精准。

---

## 二、与 customer_service/support 的差异

| 对比维度 | customer_service | ecommerce_customer_service_workflow |
|---|---|---|
| 垂直领域 | 通用客服 | 电商专属 |
| 分类数量 | 4类（含投诉） | 3类（订单/产品/其他） |
| Retrieval 位置 | Agent 内置 | 分支内独立节点 |
| 知识库隔离 | Agent 层面控制 | Retrieval 节点层面强制隔离 |

**PM 洞察**：这个模板的核心差异是**知识库隔离更彻底**——每个分支有自己的独立 Retrieval 节点，参数可以独立配置（例如产品库用向量检索，订单库用关键词检索）。

## 三、产品成熟度评估

| 评估维度 | 评分 | 说明 |
|---|---|---|
| **电商场景适配** | ★★★★★ | 三类意图直接对应电商核心业务 |
| **知识库隔离** | ★★★★★ | 独立 Retrieval 节点，隔离彻底 |
| **开箱即用性** | ★★★☆☆ | 需准备3个独立知识库 |
| **扩展性** | ★★★★☆ | 新增意图需同时加 Categorize 类别 + Retrieval + Agent |

---

## 四、迭代方向

1. **增加投诉分支**：电商投诉（差评、纠纷）是独立的高优先级场景，需要专属处理流程
2. **接入实时库存**：产品分支增加实时库存 API 调用，回答"有没有货"类问题
3. **订单状态查询**：订单分支增加 ExeSQL 节点，实时查询订单数据库
