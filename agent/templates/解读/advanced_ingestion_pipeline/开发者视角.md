# Advanced Ingestion Pipeline — 开发者视角

---

## 一、架构概览

```
File
  ↓
Parser:HipSignsRhyme（DeepDoc，pdf→markdown, word→json, image→ocr）
  ↓
Splitter:KindDingosJam（512 tokens，"\n"分割，overlap=0.002）
  ↓
Extractor:NineTiesSin（field_name="summary"，deepseek-chat）
  ↓
Extractor:TastyPointsLay（field_name="keywords"，deepseek-chat）
  ↓
Extractor:BlueResultsWink（field_name="questions"，deepseek-chat）
  ↓
Extractor:CuteBusesBet（field_name="metadata"，deepseek-chat，输出 JSON）
  ↓
Tokenizer:LegalHorsesCheer（fields="text"，embedding+full_text）
```

**canvas_category**: `"dataflow_canvas"`（摄取流水线专属类型，区别于 Agent canvas）

---

## 二、节点详解

### Parser 节点
```json
{
  "pdf": {"output_format": "markdown", "parse_method": "DeepDOC"},
  "image": {"output_format": "text", "parse_method": "ocr"},
  "word/slides": {"output_format": "json"},
  "spreadsheet": {"output_format": "html"},
  "email": {"output_format": "text", "fields": ["from", "to", "date", "subject", "body", "attachments"]}
}
```
多格式支持，PDF 使用 DeepDOC 深度解析，图片 OCR，结构化文档输出 JSON。

### Splitter 节点
```json
{
  "chunk_token_size": 512,
  "delimiters": ["\n"],
  "overlapped_percent": 0.002
}
```
按换行切分，512 tokens/片，极低重叠率（0.2%）。

### 4 个 Extractor 节点（串行）

| Extractor | field_name | 输入引用 | 输出 |
|---|---|---|---|
| NineTiesSin | `summary` | `{Splitter@chunks}` | 每片摘要 |
| TastyPointsLay | `keywords` | `{Extractor:NineTiesSin@chunks}` | Top 5 关键词，英文逗号分隔 |
| BlueResultsWink | `questions` | `{Extractor:TastyPointsLay@chunks}` | 3 个代表性问题，每行一个 |
| CuteBusesBet | `metadata` | `{Extractor:BlueResultsWink@chunks}` | JSON 字符串（名称/日期/地点/事件等） |

**数据流动**：每个 Extractor 的输入是前一个 Extractor 的 `@chunks`，实现累积精炼。

### Tokenizer 节点
```json
{
  "fields": "text",
  "search_method": ["embedding", "full_text"],
  "filename_embd_weight": 0.1
}
```
注意：`fields="text"`（索引原文），全文检索 + 向量检索双索引。

---

## 三、关键参数分析

| 参数 | 值 | 说明 |
|---|---|---|
| Splitter chunk_token_size | 512 | 标准切片大小 |
| Splitter overlapped_percent | 0.002 | 极低重叠，减少冗余摄取 |
| Extractor max_tokens | 256 | 所有 Extractor 统一 256 |
| Extractor llm_id | deepseek-chat | 4 个 Extractor 全用同一模型 |
| Extractor temperature | 0.1（未启用） | 关闭温度控制 |
| Tokenizer fields | "text" | 索引原文（非摘要） |

**注意**：Extractor max_tokens=256 对于摘要生成可能偏低（长切片的摘要可能被截断）。生产环境建议调高至 512。

## 四、摄取成本估算

```
每个切片 = 4 次 LLM 调用（summary + keywords + questions + metadata）
1000 个切片 ≈ 4000 次 deepseek-chat 调用

以 deepseek-chat 价格估算：
  输入：约 512 tokens × 4000 = 200万 tokens ≈ ¥1.2
  输出：约 256 tokens × 4000 = 100万 tokens ≈ ¥2.0
  总计：约 ¥3~5 / 1000 切片

对比基础摄取（无 Extractor）：
  成本 ≈ ¥0（纯规则处理）
```

---

## 五、部署要点

```
1. 配置 DeepSeek API Key（4 个 Extractor 全部使用）
2. 大文档预期：摄取时间 = 切片数 × 4 × LLM 延迟，可能需要几分钟到几十分钟
3. 失败处理：任一 Extractor 失败会影响后续节点（串行依赖）
4. 建议先用小文档测试端到端流程再处理大批量文档
5. metadata Extractor 输出 JSON 字符串——若 LLM 生成格式不规范会导致解析失败
```
