# Advanced Ingestion Pipeline — 产品经理视角

---

## 一、解决什么问题？

RAG 系统的核心挑战之一是**召回质量**：如果只用原始文本建立索引，检索时会受到噪声干扰（冗余词、格式字符、无关内容），导致召回结果不够精准。

Advanced Ingestion Pipeline 通过为每个切片生成四类衍生字段，让同一批文档支持**多种不同维度的检索策略**：

| 衍生字段 | 解决的检索场景 |
|---|---|
| **summary（摘要）** | 语义检索时减少噪声，提升语义匹配精度 |
| **keywords（关键词）** | 关键词精确检索，精确命中关键术语 |
| **questions（问答）** | 问答型检索，用户的问题和预生成的问题语义对齐 |
| **metadata（元数据 JSON）** | 结构化过滤（按时间/人名/地点等字段筛选） |

**核心价值主张**：一次摄取，四种召回维度——同一批文档，覆盖关键词/语义/问答/结构化过滤所有主流 RAG 检索策略。

## 二、功能设计的 PM 逻辑

### 2.1 串行 4 Extractor — 累积增强

四个 Extractor 串行执行：
```
切片 → 生成摘要 → 基于摘要提取关键词 → 基于关键词切片提问 → 基于问题切片提取元数据
```

注意：每个 Extractor 使用上一步的输出作为输入（不是原始切片），这样保证信息逐步精炼。

**PM 洞察**：串行累积的设计比并行独立生成更有效——摘要比原文噪声少，基于摘要提取的关键词质量更高；基于关键词的问题更聚焦。

### 2.2 适用场景 vs 简单摄取

| 场景 | 推荐摄取方式 |
|---|---|
| 简单 Q&A，文档量少 | 基础摄取（无 Ingestion Pipeline） |
| 需要精准语义检索 | `chunk_summary` |
| 需要多维度检索 | `advanced_ingestion_pipeline`（本模板） |
| 结构化文档（有标题） | `title_chunker` |

## 三、产品边界

### 适用场景
- 知识库问答系统（文档量大，需要高召回精度）
- 企业内部搜索（需要多维度过滤）
- 智能客服知识库（问答对齐）

### 不适用场景

| 场景 | 原因 |
|---|---|
| **实时文档摄取** | 4 个 Extractor 串行，摄取速度慢 |
| **简单文档/少量文档** | 增强字段的价值需要规模效益 |
| **高频更新文档** | 每次更新都需要重新生成四类字段，成本高 |

## 四、产品成熟度评估

| 评估维度 | 评分 | 说明 |
|---|---|---|
| **召回质量提升** | ★★★★★ | 四类字段显著提升多维检索精度 |
| **摄取成本** | ★★☆☆☆ | 4 个 LLM 调用/切片，成本明显高于基础摄取 |
| **摄取速度** | ★★☆☆☆ | 串行 Extractor，大文档摄取耗时长 |
| **配置复杂度** | ★★★☆☆ | 需要理解各 Extractor 的角色和参数 |

---

## 五、迭代方向

1. **并行 Extractor**：summary/keywords/questions/metadata 可以并行生成，大幅缩短摄取时间
2. **增量更新**：支持只对新增/变更切片重新生成字段
3. **字段选择**：允许用户选择需要的字段组合，不必全部生成
