# Generate SEO Blog — 产品经理视角

---

## 一、目标用户与核心痛点

| 用户类型 | 核心需求 | 当前痛点 |
|---|---|---|
| 内容营销团队 | 持续产出 SEO 文章，提升自然流量 | 优质内容创作耗时，产量跟不上需求 |
| 中小企业主 | 没有专职内容团队，需要低成本内容产出 | 写手贵，SEO 外包效果难控制 |
| 博客/媒体运营 | 快速扩充内容库，覆盖更多关键词 | 人工写作速度有限，内容产能是瓶颈 |
| SEO 专家 | 批量测试不同关键词的内容策略 | 每个关键词都写文章太耗时 |

**核心价值主张**：给一个主题，几分钟内输出一篇结构完整、有 SEO 意识的博客文章——把内容产能从"人/天"提升到"AI/分钟"。

## 二、功能设计的 PM 逻辑

### 2.1 三阶段流水线 — 模仿专业内容团队的工作流

```
策划（Outline Agent）→ 执行（Body Agent）→ 审校（Editor Agent）
```

这个三阶段设计完全映射了专业内容团队的工作流程：
- **不先写大纲直接写正文**：结构散乱，主题偏移风险高
- **分工专职**：每个 Agent 只做一件事，专注度更高，质量更稳定

**PM 洞察**：这也是这个模板与"单 Agent 写全文"方案的核心差异。单 Agent 同时处理结构、内容、SEO，容易顾此失彼。分工流水线的质量更稳定。

### 2.2 TavilySearch — 让内容基于真实信息

Outline Agent 联网搜索参考资料，确保大纲基于实际存在的权威内容，而非 LLM 凭记忆编造。

**PM 洞察**：这是 AI 内容创作的核心信任问题——没有联网搜索的 AI 写作容易产生"看起来合理但实际错误"的内容，对 SEO 有害（Google 会惩罚低质量内容）。

### 2.3 Editor Agent 的 SEO 意识

最后一个 Agent 专门做 SEO 优化：
- 关键词密度调整
- 标题/小标题的 H1/H2/H3 结构
- Meta description 生成
- 内容可读性改善（Flesch 指数等）

## 三、产品边界

### 适用场景
- 技术博客、行业知识文章
- 产品介绍和功能说明文章
- 问答型 SEO 内容（"什么是 X"、"如何做 Y"）

### 不适用场景

| 场景 | 原因 |
|---|---|
| **新闻/时事文章** | LLM 知识有截止日期，需要实时信息 |
| **高度专业的学术内容** | AI 可能生成看起来正确但有误的专业知识 |
| **品牌故事/创意内容** | 需要独特品牌声音，AI 输出较同质化 |
| **直接发布无需审核** | AI 内容必须人工审核后才能发布 |

## 四、产品成熟度评估

| 评估维度 | 评分 | 说明 |
|---|---|---|
| **需求真实性** | ★★★★★ | 内容营销是企业 SEO 的核心需求 |
| **内容质量稳定性** | ★★★★☆ | 三阶段分工保证结构质量，但内容深度依赖 prompt |
| **SEO 专业性** | ★★★☆☆ | 基础 SEO 结构有，但专业 SEO 工具（关键词分析等）需另配 |
| **内容同质化风险** | ★★★☆☆ | 大量使用同一模板会导致内容风格趋同 |

---

## 五、迭代方向

1. **关键词分析前置**：在 Outline 前增加关键词搜索量/竞争度分析，选择最有价值的切入角度
2. **品牌声音定制**：在 Editor Agent 中注入品牌 tone of voice 指南，降低同质化
3. **批量生成**：支持输入关键词列表，批量生成一组博客文章
