# User Interaction — 开发者视角

---

## 一、节点类型全景

| 节点类型 | 实例 | 作用 | 是否新出现 |
|---|---|---|---|
| `Begin` | begin | 对话入口，接收用户问题 | — |
| `Agent` | Planning Agent | 分析需求，制定执行计划 | — |
| `UserFillUp` | 审批节点 | **暂停流程，等待人工输入/确认** | **首次出现** |
| `Agent` | Search Agent | 按确认后的计划执行搜索和生成 | — |
| `Message` | 输出节点 | 展示最终结果 | — |

**`UserFillUp` 节点**是这个模板的核心创新，是 RAGFlow 平台中实现 Human-in-the-Loop 的专用节点类型。

---

## 二、数据流分析

```
begin
  └── sys.query（用户初始问题）
          │
          ↓
Planning Agent
  输入：sys.query
  任务：分析需求，输出详细执行计划
  输出：@content（计划文本）
          │
          ↓
UserFillUp（人工审批节点）
  展示：Planning Agent 的计划内容
  行为：流程暂停，界面呈现给用户
  用户操作：
    ① 直接确认（使用 AI 的计划）
    ② 修改计划后确认
    ③ 取消（终止流程）
  输出：用户确认/修改后的内容 → @result
          │
          ↓
Search Agent
  输入：sys.query + UserFillUp@result（确认后的计划）
  任务：按计划执行搜索、整合信息、生成回答
  工具：TavilySearch 或 Retrieval（取决于配置）
  输出：@content（最终回答）
          │
          ↓
Message
  内容：{Search Agent@content}
```

---

## 三、UserFillUp 节点工作机制

`UserFillUp` 是 RAGFlow 的**同步等待节点**，工作原理：

1. 流程执行到此节点时，**立即暂停**
2. 将上游输出（Planning Agent 的计划）渲染到用户界面
3. 界面呈现一个**可编辑的文本框**，预填入 AI 的计划
4. 等待用户操作：
   - **确认**：将文本框内容（原始或修改后）作为输出传递给下游
   - **取消**：流程终止
5. 用户确认后，流程从 UserFillUp 的下游节点继续执行

**关键特性**：
- 支持用户**直接修改** AI 输出的内容
- 修改后的内容会作为下游节点的输入，实现"人工纠偏"
- 流程在此节点的等待**没有超时机制**（当前版本），需人工主动操作

---

## 四、关键设计问题

### 问题：无超时处理
`UserFillUp` 等待用户确认时没有超时机制，如果用户关闭页面或长时间不响应，流程会永久挂起。在生产环境中需要考虑超时清理机制。

### 问题：Planning Agent 的输出质量决定审批体验
如果 Planning Agent 的计划写得模糊或错误，用户在审批界面需要大量修改，失去了 AI 辅助的意义。system prompt 的质量至关重要。

## 五、可扩展点

```
增加风险评估（在 Planning 后、UserFillUp 前）
  Planning Agent → Risk Classifier（Categorize）
    ├── 低风险 → 跳过 UserFillUp，直接执行
    └── 高风险 → 触发 UserFillUp 人工审批

增加审批记录
  UserFillUp 后增加数据库写入节点
  记录：原始计划、修改内容、用户ID、时间戳

多人审批（串行）
  UserFillUp1（初审）→ UserFillUp2（复审）→ 执行
```

---

## 六、落地配置要点

```
1. 定制 Planning Agent 的 system prompt：
   - 明确计划的格式（让审批人易于阅读和修改）
   - 例：输出 Markdown 格式的步骤列表，每步有预期结果

2. 定制 Search Agent 的 system prompt：
   - 说明如何解读 UserFillUp 的输出（用户确认的计划）
   - 例："请严格按照以下计划执行，不要自行扩展"

3. 配置 UserFillUp 的展示文案：
   - 告知用户可以修改的范围
   - 提供明确的确认/取消指引
```
