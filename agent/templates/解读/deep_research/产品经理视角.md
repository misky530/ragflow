## 一、目标用户与核心痛点

这个模板的 system prompt 直接写明了定位：**"战略研究总监，拥有20年咨询经验"**——这定义了产品的服务对象和输出标准。

| 用户类型 | 核心需求 | 当前痛点 |
|---|---|---|
| 销售/BD | 快速了解客户行业、竞争格局 | 开会前临时抱佛脚，信息碎片化 |
| 市场/营销 | 竞品分析、趋势洞察 | 分析师资源稀缺，人工研究周期长 |
| 政策/合规 | 政策解读、监管影响分析 | 法规文件繁杂，解读需要专业背景 |
| 咨询顾问 | 快速构建行业基础知识 | 新项目启动阶段信息密集但时间紧 |

**核心价值主张**：把原本需要 3-8 小时人工研究的工作，压缩到 10-16 分钟，输出麦肯锡/BCG 标准的结构化报告。

## 二、功能设计的 PM 逻辑

### 2.1 三类查询策略 — 需求分类是产品成熟度的体现

系统 prompt 内置了三种研究模式，会根据用户问题自动选择：

| 查询类型 | 典型例子 | 策略 |
|---|---|---|
| **Depth-first（深度优先）** | "分析苹果供应链风险" | 多角度挖掘单一主题 |
| **Breadth-first（广度优先）** | "今年AI领域有哪些重大进展" | 分解子问题，并行覆盖多维度 |
| **Straightforward（直接查询）** | "ChatGPT的订阅价格是多少" | 高效直接，不过度研究 |

**PM 洞察**：查询分类的本质是**资源调度的智能化**——避免用户问一个简单问题却等了15分钟。一个成熟产品不会对所有输入用同一策略。

### 2.2 质量门控 — 产品 SLA 的落地

每个阶段都有硬性通过标准：

- **Stage 1**：必须找到 ≥5 个优质 URL，来源多样性（30%学术/25%官方/25%行业/20%新闻）
- **Stage 2**：80%+ 提取成功率，否则触发 fallback
- **Stage 3**：报告 ≥2000 词，执行摘要（400词）+ 分析（1200词）+ 建议（400词）

**PM 洞察**：这些量化指标是**用户体验保障的 SLA**。没有门控，产品可能在信息不足时输出一份看起来完整但实质空洞的报告——这是 AI 产品最常见的质量陷阱。

### 2.3 信源标注系统 — 建立用户信任的核心机制

提取内容会被标注可信度标签：

- `[FACT]` — 可验证事实
- `[PREDICTION]` — 未来预测
- `[OPINION]` — 专家观点
- `[UNVERIFIED]` — 缺乏来源的声明
- `[BIAS_RISK]` — 可能存在利益冲突

**PM 洞察**：这个标注系统解决了 AI 报告的最大信任危机——用户不知道哪些是可靠事实，哪些是 AI 推断。通过显式标注，产品将辨别责任从用户侧转移到系统侧，大幅降低使用门槛。

### 2.4 Fallback 策略 — 产品韧性设计

三个阶段都内置失败处理：

- 搜索失败 → 调整关键词策略重试
- 内容提取失败 → 标记不可用，用已有内容补充
- 合成不足 → 降低输出标准但明确说明数据局限

**PM 洞察**：没有 fallback 的 AI 产品，遇到边界情况时会给出误导性的置信输出。这里的设计说明团队对失败模式有清醒认知。

## 三、产品边界

### 适用场景

- 竞品分析、行业动态研究
- 政策解读、监管影响分析
- 投资标的初步尽调
- 技术方案选型调研

### 不适用场景

| 场景 | 本质原因 | 替代方案 |
|---|---|---|
| **查实时数据** "Tesla今天股价" | Tavily 有爬取延迟 | Bloomberg / 股票 App |
| **精确历史数字** "Q3确切营收" | 多来源数据可能矛盾 | SEC Edgar / 官方财报 |
| **私有内部信息** "我们公司数据" | 只搜公开网页 | RAGFlow 知识库模式 |
| **快问快答** "帮我翻译这句话" | 链路耗时5-15分钟 | 普通 Chat 模式 |
| **法律/医疗精准建议** | 幻觉风险不可接受 | 专业人士 + AI 辅助 |
| **高频监控** "每分钟监控舆情" | Tavily 成本高，不适合高频 | 专用舆情系统 |

**PM 洞察**：清晰的边界定义是产品成熟的标志。这个模板通过 system prompt 设计让 agent 主动说自己不能做什么——这是产品诚信设计。

## 四、产品成熟度评估

| 评估维度 | 评分 | 说明 |
|---|---|---|
| **需求清晰度** | ★★★★★ | 目标用户、使用场景、边界都明确 |
| **架构设计** | ★★★★★ | Orchestrator-Worker 分工合理，模型选型有考量 |
| **质量保障** | ★★★★☆ | 有质量门控，但缺乏输出结果验证机制 |
| **开箱即用性** | ★★★☆☆ | 依赖特定模型 API，新用户配置门槛高 |
| **可扩展性** | ★★★★☆ | 架构清晰，但工具依赖 Tavily，扩展受限 |
| **商业化就绪度** | ★★★☆☆ | 成本结构需优化才适合规模化 |

## 五、迭代方向建议

**短期**

1. **模型无关化**：增加模型配置层，允许替换为 OpenAI / Claude / 本地模型，降低使用门槛
2. **知识库融合**：增加子 Agent 检索用户的 RAGFlow 知识库，实现"公开信息 + 私有数据"混合研究

**中期**

3. **成本可见性**：执行前显示预估 API 调用成本，帮助企业用户做决策
4. **增量研究模式**：支持在已有报告基础上继续深挖子议题，而非每次从零开始

**长期**

5. **输出格式扩展**：除 McKinsey 报告外，支持导出 PPT 提纲、Excel 数据表、简报摘要
